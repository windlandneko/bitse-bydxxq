# SQLite 数据库函数调用说明

## 1. 说明与约定

本文是数据库服务层的调用契约，供 Qt 用户端、Qt 管理端、Socket 服务和 Web 看板实现时使用。当前仓库已经提供可直接打开的数据库文件 `database/charging_platform.db`，建库和种子脚本分别为 `database/schema.sql`、`database/seed.sql`。

下文函数名是建议的 `DatabaseManager` 接口名，不代表仓库中已经存在对应 C++ 实现。函数内部必须使用参数绑定，不能拼接用户输入。

- 数据库驱动：Qt `QSQLITE`；每个工作线程创建并使用自己的 `QSqlDatabase` 连接。
- 时间：传入/传出 ISO-8601 UTC 文本，例如 `2026-09-04T01:00:00Z`。
- 金额：服务层按“分”或 Decimal 计算后，以字符串/数值参数写入 `NUMERIC` 字段，禁止用二进制浮点直接累计余额。
- 成功返回业务对象或 `true`；失败返回 `false`/错误对象，必须保留 SQLite 错误码和 `lastError().text()`。
- 写操作成功后提交事务，失败时回滚；不要在函数内部吞掉异常或返回“看似成功”的默认值。

## 2. 打开连接和初始化

### `open`

```cpp
bool open(const QString& dbPath);
```

调用一次后执行以下连接级设置：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

`dbPath` 指向 `database/charging_platform.db`。服务端启动时检查 `PRAGMA integrity_check`；返回值不是 `ok` 时停止业务写入并记录错误。

### `initializeSchema`

```cpp
bool initializeSchema(const QString& schemaFile);
```

首次部署读取并执行 `database/schema.sql`。脚本使用 `CREATE TABLE/INDEX/VIEW IF NOT EXISTS`，可安全重复执行。`database/seed.sql` 只用于开发/演示环境，不应在生产启动时自动执行。

## 3. 用户和钱包

### `findOrCreateUserByPhone`

```cpp
User findOrCreateUserByPhone(const QString& phone);
```

先按 `users.phone` 查询；不存在时在同一事务插入 `status='active'`、默认昵称和零余额。手机号应在调用前校验并规范化。若查询到 `frozen/disabled`，仍返回用户状态，由上层阻止预约和充电。

### `rechargeWallet`

```cpp
WalletTransaction rechargeWallet(qint64 userId,
                                 const QString& amount,
                                 const QString& idempotencyKey);
```

事务步骤：锁定/读取用户余额、确认用户为 `active`、更新 `users.wallet_balance` 和 `version`、插入 `wallet_transactions(transaction_type='recharge')`。`idempotencyKey` 重复时返回第一次成功的流水，不得再次加余额。金额必须大于 0。

### `listWalletTransactions`

```cpp
QList<WalletTransaction> listWalletTransactions(qint64 userId,
                                                int limit,
                                                int offset);
```

查询 `wallet_transactions`，按 `created_at DESC, id DESC` 分页。用户端只能传入当前登录用户的 `userId`；管理端查看他人流水必须经过权限校验。

## 4. 电站、电桩和预约

### `listStationAvailability`

```cpp
QList<StationAvailability> listStationAvailability(
    const QString& regionCode,
    double latitude,
    double longitude,
    int limit);
```

读取 `v_station_availability`，按区域过滤后在服务层计算距离并排序；价格从当前生效的 `tariffs` 查询。没有区域条件时传空字符串。该函数只读，不开启写事务。

### `createReservation`

```cpp
Reservation createReservation(qint64 userId,
                               qint64 chargerId,
                               const QString& reservationNo,
                               const QString& idempotencyKey,
                               const QString& reservedAt,
                               const QString& expiresAt);
```

必须使用 `BEGIN IMMEDIATE`：

1. 查询用户状态、未完成订单和有效会话；
2. 查询目标电桩并确认 `status='idle'`；
3. 插入 `reservations(status='active')`；
4. 更新 `chargers.status='reserved', version=version+1`；
5. 插入 `charger_status_history` 和 `outbox_events`；
6. 提交。

`idempotency_key`、部分唯一索引和事务锁共同防止重复预约。遇到 `SQLITE_BUSY` 可按固定次数重试，不能无限等待。

### `cancelReservation`

```cpp
bool cancelReservation(qint64 userId, qint64 reservationId,
                       const QString& reason);
```

只允许 `active` 状态取消；同一 `BEGIN IMMEDIATE` 中将预约置为 `cancelled`，并将仍为 `reserved` 的电桩恢复为 `idle`，写状态历史。`started/completed` 预约不能通过该函数取消。

## 5. 充电会话和结算

### `startChargingSession`

```cpp
ChargingSession startChargingSession(qint64 userId,
                                     qint64 reservationId,
                                     const QString& sessionNo,
                                     const QString& idempotencyKey,
                                     const QString& startedAt);
```

事务内确认预约属于用户且状态为 `active`，电桩状态为 `reserved`；插入 `charging_sessions(status='charging', idempotency_key=...)`，更新预约为 `started`、电桩为 `charging`，并写状态历史/事件。重复 `idempotencyKey` 或同一 `reservationId` 请求时，查询并返回已创建的会话，不重复插入。

### `updateChargingProgress`

```cpp
bool updateChargingProgress(qint64 sessionId,
                            const QString& meterEndKwh,
                            int durationSeconds,
                            const QString& soc,
                            const QString& updatedAt);
```

仅允许 `preparing/charging/interrupted` 会话更新。定时器仿真的高频采样可以留在内存；开始、暂停、恢复、异常和结束等关键节点必须持久化到 `charging_sessions`。

### `settleChargingSession`

```cpp
SettlementResult settleChargingSession(qint64 sessionId,
                                       const QString& endedAt,
                                       const QString& idempotencyKey);
```

使用 `BEGIN IMMEDIATE`，按以下顺序执行：锁定会话和用户、计算电量/时长、读取生效价格、插入唯一订单、检查余额。余额不足时订单为 `payment_failed`，不扣余额；余额足够时更新余额、插入负金额 `wallet_transactions(transaction_type='charge')`、订单置 `paid`、会话置 `settled`、电桩恢复 `idle` 并累加统计。重复调用通过 `session_id UNIQUE` 和流水幂等键返回已完成结果。

## 6. 管理端、统计和事件

### `setUserFrozen`

```cpp
bool setUserFrozen(qint64 adminId, qint64 userId,
                   bool frozen, const QString& reason,
                   const QString& requestId);
```

更新 `users.status/freeze_reason/version`，并在同一事务写入 `admin_audit_logs(before_json, after_json)`。冻结只阻止新预约和启动充电，不删除历史订单。

### `getDashboardSummary`

```cpp
DashboardSummary getDashboardSummary(const QString& fromDate,
                                     const QString& toDate);
```

营收和订单优先读取 `station_daily_stats`；需要核对时读取只读视图 `v_daily_revenue`。设备数量读取 `v_station_availability`。Web 看板账号只能执行 SELECT。

### `writeLoadForecast`

```cpp
bool writeLoadForecast(const LoadForecast& forecast);
```

写入 `load_forecasts`，唯一键为站点、预测区间和模型版本；重复写入同一版本应使用 upsert 或返回已存在记录，不覆盖其他模型版本。

### `publishPendingEvents`

```cpp
int publishPendingEvents(int batchSize);
```

查询 `outbox_events.status IN ('pending', 'failed')`、`retry_count < maxRetryCount` 且到达 `next_retry_at`（空值按当前时间处理）的事件，发布成功后置为 `published`；失败则增加 `retry_count`、记录下次重试时间并保持 `failed`，使后续调用仍能取到待重试事件；超过最大次数后才转入人工处理队列。事件发布器不能直接修改订单、余额等交易事实。

## 7. 事务和线程注意事项

- Qt 的 `QSqlDatabase` 连接不能跨线程复用；每个线程使用唯一连接名，线程退出前关闭并移除连接。
- 预约、开始/结束充电、充值和冻结用户使用 `BEGIN IMMEDIATE`；普通查询使用默认只读事务。
- 所有 `QSqlQuery` 使用 `prepare()` + `bindValue()`；禁止把手机号、订单号、搜索关键字拼接进 SQL。
- 发生约束冲突时根据 `lastError().nativeErrorCode()` 区分唯一键、外键和忙锁错误，并转换为统一业务错误码。
- 备份前执行 `PRAGMA wal_checkpoint(TRUNCATE)`，再复制 `.db` 文件；恢复后重新执行完整性检查。
