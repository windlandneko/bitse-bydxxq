# 数据库服务层调用说明

本文只定义当前阶段需要的数据库服务层边界。函数名是建议接口，不代表仓库已经有对应的 C++ 实现。实现统一使用 Qt `QSQLITE`、参数绑定和事务，不把 SQL 暴露给客户端。

## 1. 通用约定

- 每个工作线程使用自己的 `QSqlDatabase` 连接，不能跨线程复用连接。
- 时间使用 UTC ISO-8601 文本；金额由服务层按 Decimal/分计算后写入。
- 写操作成功提交，失败回滚；保留 SQLite 原始错误码并转换为业务错误。
- 重复请求优先通过幂等键查询原结果，不重复创建预约、订单或流水。
- `schema.sql` 用于建库，`seed.sql` 只用于开发/演示环境。

## 2. 连接与初始化

### `open`

```cpp
bool open(const QString& dbPath);
```

打开数据库后设置：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

### `initializeSchema`

```cpp
bool initializeSchema(const QString& schemaFile);
```

执行 `database/schema.sql`。建表、索引和视图均可重复执行。本期不维护 `schema_version`，结构变化通过后续 PR 处理。

## 3. 用户与钱包

### `findOrCreateUserByPhone`

按 `users.phone` 查询；不存在时在事务内创建 active 用户、昵称 `用户`+手机号后四位和零余额。手机号按文本保存，格式校验由服务层决定。冻结或禁用用户仍返回状态，由业务层阻止预约和充电。

### `rechargeWallet`

读取当前余额，确认用户可操作，更新 `users.wallet_balance`，插入正金额的 `wallet_transactions`，同时递增 `version`。金额必须大于 0，重复幂等键返回原流水。

### `listWalletTransactions`

按用户和创建时间倒序分页读取钱包流水。用户端只能读取当前登录用户；管理员查看他人流水需先通过权限校验。

## 4. 站点、费率与预约

### `listStationAvailability`

读取 `v_station_availability`，按区域过滤，在服务层计算距离并排序；费率读取对应站点和桩类型的当前 `tariffs` 记录。数据库不处理地图路线和距离公式。

### `upsertTariff`

按 `(station_id, charger_type)` 写入当前费率。当前不传递生效结束时间，也不做费率区间重叠校验。结算时把当前单价复制到订单，后续调价不改变历史订单。

### `createReservation`

```cpp
Reservation createReservation(qint64 userId,
                               qint64 chargerId,
                               const QString& reservationNo,
                               const QString& idempotencyKey,
                               const QString& reservedAt,
                               const QString& expiresAt);
```

使用 `BEGIN IMMEDIATE`：检查用户状态、在途订单和有效会话；确认电桩为 `idle`；插入 `active` 预约、更新电桩为 `reserved`、写入状态历史后提交。部分唯一索引和幂等键负责防重复。

### `cancelReservation`

只允许取消 `active` 预约。在同一事务中写入 `cancelled` 和 `ended_at`，并将仍为 `reserved` 的电桩恢复为 `idle`、记录状态历史。

## 5. 充电与结算

### `startChargingSession`

检查预约属于当前用户且为 `active`，电桩为 `reserved`；在事务内插入会话、将预约置为 `started`、将电桩置为 `charging`，并写状态历史。

### `updateChargingProgress`

只更新 `preparing`、`charging` 或 `interrupted` 会话的计量、时长和 SoC。高频仿真采样可留在内存，开始、暂停、恢复、异常和结束等关键节点写入会话。

### `settleChargingSession`

在一个 `BEGIN IMMEDIATE` 事务中完成：读取会话和用户、计算费用、创建订单、执行扣款、写钱包流水、更新订单/会话/电桩及累计数据。

扣款前余额大于 0 时允许本次扣款，扣款后余额可以为负并显示欠费；扣款前余额小于等于 0 时返回业务错误，不产生新的扣款流水。订单价格使用结算时快照。会话唯一键、扣款订单唯一索引和幂等键共同保证重复结算不会重复扣款。

## 6. 管理、看板与预测

### `setUserFrozen`

更新用户状态和冻结原因，并在同一事务中追加 `admin_audit_logs`。冻结只阻止新预约和启动充电，不删除历史数据。

### `getDashboardSummary`

设备状态读取 `v_station_availability`；营收和电量读取 `v_daily_revenue` 或直接聚合 `orders`。当前不读取或维护日报汇总表，避免交易事实和缓存数据不一致。

### `writeLoadForecast`

写入 `load_forecasts`，使用 `(station_id, horizon_start, horizon_end, model_version)` 防止同一模型重复写入；`is_peak` 由预测程序计算。

数据库本期不持久化消息 outbox。需要 Socket/Web 刷新时，由服务层在事务提交后发送通知，通知失败不修改已经提交的订单和余额事实。

## 7. 事务与错误处理

- 预约、开始/结束充电、充值、冻结用户和费率修改使用写事务；普通列表查询只读。
- 所有外部输入使用 `prepare()` + `bindValue()`，禁止拼接 SQL。
- `SQLITE_BUSY` 只做有限次重试；唯一键、外键和 CHECK 冲突转换为明确的业务错误。
- 服务启动或恢复数据库时可执行 `PRAGMA integrity_check`；异常时停止写入并记录日志。
