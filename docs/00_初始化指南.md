# 初始化指南

## 环境与安装

目标环境是 Ubuntu 22.04及以上，虚拟机需启用图形桌面；WSL使用WSLg。
编译工具为CMake、C++17和Qt 6.2+，IDE使用Qt Creator 6.2+。Ubuntu22.04自带Qt库6.2.4
满足要求，但发行版的Qt Creator可能较旧，IDE请从Qt官方安装器选6.2或更新版本；命令行
构建不依赖IDE。中文显示需要Noto CJK字体。

```bash
# 默认安装：sudo仅用于apt系统包，其余工具安装到当前用户目录
bash scripts/setup_env.sh

# 已有依赖时只检查，不安装
bash scripts/setup_env.sh --check

# 按需分别安装系统包 / 用户工具
bash scripts/setup_env.sh --system-only
bash scripts/setup_env.sh --tools-only
```

系统包完整清单可用 `--print-packages` 查看，包含Qt Widgets、SQL SQLite插件、Charts、
Quick/QML运行模块、WebEngine及其辅助进程、字体和无显示测试工具。用户工具固定安装
Node.js24.20.0、pnpm10.33.0、uv0.12.9（位于 `~/.local/opt/charging-tools`）。Node归档校验
官方SHA256；不运行远程root安装脚本。已有手动工具也可使用，Node最低22、Python最低3.10，
pnpm和Python依赖以仓库锁文件为准。

当前开发机没有sudo权限，使用本机已有Qt基础库和用户目录解包的Qt附加模块。
`scripts/qt-env.sh` 支持可选 `CHARGING_QT_PREFIX`；标准apt安装不需要这个变量。
该本机依赖目录和所有构建产物均不提交，不是其他同学复现的前提。

## 构建和测试

```bash
bash scripts/build.sh
bash scripts/test.sh
```

build会锁定安装Web和Python依赖，再构建三个C++程序、GUI测试和Web生产页面。
默认目录 `build/full`，可通过 `CHARGING_BUILD_DIR`、`CHARGING_BUILD_JOBS`、
`CHARGING_BUILD_TYPE` 调整，例如：

```bash
CHARGING_BUILD_DIR=build/debug CHARGING_BUILD_TYPE=Debug bash scripts/build.sh
CHARGING_BUILD_DIR=build/debug bash scripts/test.sh
```

所有脚本自动加载用户工具路径及可选Qt运行路径。手动运行CMake、ctest或二进制时，
若依赖安装在用户目录，可先 `source scripts/qt-env.sh`。Qt Creator直接打开根目录的
CMakeLists，选择Qt6 Kit；通过 `CHARGING_SERVER_URL` 在Run Environment配置服务地址。
CMakePresets也保留debug/release预设。

测试包含C++格式、Python Ruff、Web Oxlint/Oxfmt、五个CTest入口。业务测试自动启动
随机端口服务并使用临时数据目录，不消耗腾讯配额，也不修改演示钱包。Web生产构建在
build脚本完成，类型错误会直接失败。CI在Ubuntu22.04重复完整构建与验收。

## 启动和配置

```bash
# 终端1（保持运行），静态Web与API在同一端口
bash scripts/run.sh server
# 终端2
bash scripts/run.sh user
# 终端3
bash scripts/run.sh admin
```

大屏地址 `http://127.0.0.1:8080`。默认管理员 **admin / 123456**。用户手机号为以1开头的
11位数字，自动注册默认昵称；两个演示账号为 **13800000001 / 13800000002**。充值、
充电和重启是模拟功能，页面有说明。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `--host` | 127.0.0.1 | 仅本机；课堂跨机可显式监听0.0.0.0 |
| `--port` | 8080 | 0代表自动分配，stdout输出LISTENING地址 |
| `--data-dir` / `CHARGING_DATA_DIR` | 仓库data | SQLite、地图配置、头像和日志 |
| `--web-root` | 仓库web/dist | Vite生产文件 |
| `--source-root` | 仓库根目录 | Python模块所在父目录 |
| `--time-scale` | 60 | 1到3600，模拟充电加速；预约超时仍为现实15分钟 |
| `--no-seed` | 关闭 | 初次仅建管理员和空业务库，后续重启不补演示数据 |
| `CHARGING_SERVER_URL` | http://127.0.0.1:8080 | 两个客户端连接地址 |
| `CHARGING_UV` | uv | 后台使用的uv可执行文件 |

仓库移动后重新构建，或通过run脚本启动以明确source-root/web-root。结束后台用Ctrl+C，
服务清理预测进程并关闭工作线程。后台启动失败会写 `data/logs/server-日期.log`。
端口占用时换端口并同步客户端地址。

## 腾讯地图

后台地址解析需要在腾讯位置服务控制台启用WebService API。配置本机文件：

```json
{
  "key": "在本机填写WebService Key",
  "secret": "启用SN校验时填写SecretKey，否则留空"
}
```

保存为 `data/map-settings.json`，执行 `chmod 600 data/map-settings.json`；自定义data-dir
时配置文件随目录放置。也可通过 `TENCENT_MAP_KEY`、`TENCENT_MAP_SECRET` 环境变量覆盖。
这些值不需要交给浏览器，不要写进源码、截图或PR。

签名对原始参数按名称排序，拼接路径、查询及SK求MD5，传输时再编码各参数；遵循
[腾讯WebService签名规则](https://lbs.qq.com/faq/serverFaq/webServiceKey)。地址解析由后台
异步请求腾讯完成；预设区域是软件层面的GPS模拟。Key未配置、网络失败或每日额度耗尽
均有对应提示，仍可选择预设区域。2026-09-05验收期间Key配额达到上限，记录于验收报告。

导航在用户端实际QWebEngineView加载腾讯地图，传当前坐标、目标站点坐标与出行方式，
支持驾车/步行。使用
[腾讯URI路线规划](https://lbs.qq.com/webApi/uriV1/uriGuide/uriWebRoute)
和移动User-Agent；地图仍须外网访问。Qt地图正常使用Chromium沙箱，使用普通用户运行。

## 常见问题

- **QML模块未安装 / 页面空白**：运行system-only补齐qml6运行包，再运行mobile-qml-smoke；
  只装qt6-base-dev不足以运行手机UI。
- **找不到QtWebEngineProcess / icudtl.dat / locales**：补齐Qt WebEngine工具和依赖。
  可选用户Qt前缀模式由build脚本同时生成应用与辅助进程的qt.conf，Qt6.2仅设资源环境变量
  不足以定位资源。不要把禁用沙箱当作常规解决办法。
- **没有DISPLAY**：API和大屏服务可以无图形运行；GUI需桌面/WSLg。自动测试使用offscreen
  与软件渲染，不需要为了后端安装完整桌面。
- **大屏404**：先运行build生成web/dist，再启动服务；业务数据没有静态JSON自动兜底。
- **预测未生成**：确认uv可执行、ml依赖已同步；管理端运行预测并查看状态/服务日志。
  保留旧预测时会显示生成时间，不能把失效数据当作实时结果。
- **旧库打不开**：保留旧文件，使用新data-dir。项目没有破坏式自动迁移脚本。

Web单独开发使用 `pnpm --dir web dev`，Vite代理 `/api` 到8080，后台仍须启动。
公开数据回测与下载来源见 `ml/README.md`；它不影响普通演示环境的首次运行。
