# 统一接口与实现约定

本文件是本次实现的接口合同。需求依据仅为 `reference/东软电动汽车充电桩应用管理平台项目要求书.md`。用户已确定 C++/Qt 后端、Qt Quick/QML 用户端、Qt Widgets 管理端。目标兼容 Ubuntu 22.04 的 Qt 6.2.4。

## 通信

单独的 `charging-server` 进程监听 `127.0.0.1:8080`（可配置）。使用 QTcpServer/QTcpSocket 实现有长度限制的 HTTP/1.1 请求，工作线程拥有数据库连接；GUI 不连接数据库。浏览器通过同一服务器获得 web/dist 静态资源与统计接口。

POST /api/rpc，JSON `{ "action": "user.login", "params": {...} }`。登录后 Authorization: Bearer TOKEN。
成功 `{ "ok": true, "data": ... }`；失败 `{ "ok": false, "error": {"code":"...", "message":"中文说明"} }`。
GET /api/health -> `{ok:true,data:{status:"ok",...}}`。
GET /api/dashboard -> 大屏数据对象（不包 ok/data），无个人信息，只读聚合。

时间为 ISO8601 UTC（Z），界面显示本地时间，业务日界固定 Asia/Shanghai。
所有金额字段以整数分存储/传输，如 balanceCents、amountCents、priceCents（分/kWh）。展示除以100。电量 energyKwh 为数值，功率 powerKw 为数值。

## 共享 Qt 客户端

CMake target `charging-client`，包含目录 shared/，头文件 `ApiClient.h`。
`ApiClient : QObject`：
- Q_PROPERTY QString baseUrl READ baseUrl WRITE setBaseUrl NOTIFY baseUrlChanged；默认 CHARGING_SERVER_URL 或 http://127.0.0.1:8080。
- Q_PROPERTY QString token READ token WRITE setToken NOTIFY tokenChanged。
- Q_INVOKABLE void request(QString action, QVariantMap params = {}, QString tag = {})。
- signals: succeeded(QString tag, QVariant data)；failed(QString tag, QString message, QString code)。QML 可以直接消费 JS 对象/数组。
- C++ `void call(const QString &action, const QJsonObject &params, std::function<void(QJsonValue)> success, std::function<void(QString)> failure = {})`。
- 登录返回时自动保存 token；auth.logout 成功清空 token。
- 异步超时和网络错误提示；写操作不隐式重试。

## DTO

User: {id,phone,nickname,avatarUrl,balanceCents,status:'active'|'frozen',createdAt}
Charger: {id,stationId,code,type:'dc'|'ac',powerKw,status:'idle'|'reserved'|'charging'|'fault'|'offline'|'restarting',chargingCount,chargingSeconds,energyKwh}
Station: {id,code,name,address,region,latitude,longitude,priceCents,totalChargers,idleChargers,onlineRate,distanceKm,recommended,predictedAvailableChargers,forecastAt}
Order: {id,orderNo,userId,stationId,stationName,chargerId,chargerCode,chargerType,powerKw,status:'reserved'|'charging'|'pending_payment'|'paid'|'cancelled',createdAt,expiresAt,startedAt,endedAt,energyKwh,durationSeconds,amountCents,priceCents,soc,stopReason,balanceCents}
订单展示以上字段始终存在；无时间用空字符串。

## 用户动作

- user.login {phone} -> {token,user:User}；新手机号自动注册。冻结不能新登录。
- auth.logout {} -> {}。
- user.me {} -> User。
- user.update {nickname?,avatarBase64?} -> User。头像提供 PNG/JPEG 原文件 base64，服务器校验并存储，返回 /uploads/... URL；最大2MB。
- wallet.recharge {amountCents,idempotencyKey} -> User。范围1..1000000分，幂等键 UUID。
- location.presets {} -> [{name,latitude,longitude}]，无需登录。
- location.geocode {address} -> {name,latitude,longitude}，通过腾讯地址解析；缺 key 明确错误。
- stations.list {latitude?,longitude?,query?,region?,sort?:'distance'|'price'|'idle',fastOnly?:bool} -> [Station]，无需登录。
- stations.detail {stationId,latitude?,longitude?} -> {station:Station,chargers:[Charger]}。
- orders.list {} -> [Order]（当前用户，时间倒序）。
- orders.active {} -> Order 或 null（reserved/charging/pending_payment）。
- orders.reserve {chargerId,idempotencyKey} -> Order。一个用户一个在途订单，一个桩一个占用。余额须 > 0。
- orders.start {orderId} -> Order。保存本次价格、功率、时间倍率和可用余额上限；同一订单重复开始返回现状。
- orders.cancel {orderId} -> Order，仅预约可取消，释放电桩。
- orders.stop {orderId} -> Order，服务端结束计费，释放电桩，进入 pending_payment。
- orders.settle {orderId} -> Order，原子扣费和写流水；重复请求返回原小票。
- orders.get {orderId} -> Order，仅本人。

预约15分钟超时。充电服务端计时，默认60倍速（启动参数可改），客户端退出后继续。余额达到起充时预算或模拟60kWh电池充满时停止，待结算，余额不为负。冻结禁止新预约与开始，已有订单仍能停止、结算。重新进入充电流程遇充电中/待支付订单必须提示并转结算处理页；预约可继续/取消。

## 管理员动作

- admin.login {username,password} -> {token,username}，默认 admin/123456。
- admin.overview {days?:7|30} -> {todayRevenueCents,monthRevenueCents,totalRevenueCents,todayOrders,statusCounts:[{status,label,count,percent}],revenueTrend:[{date,revenueCents,orderCount}]}。
- admin.stations {} -> [Station]。
- admin.station.save {id?,name,address,region,latitude,longitude,priceCents,chargerCount?,powerKw?,type?:'dc'|'ac'} -> Station。新增默认混合快慢充，chargerCount 必填1..100，事务批量建桩。
- admin.chargers {stationId?,status?,query?} -> [Charger + stationName]。
- admin.charger.restart {chargerId} -> {message}。占用中拒绝重启，其他进入 restarting，服务端模拟指令处理后恢复 idle，记录运维日志。
- admin.charger.status {chargerId,status:'fault'|'idle'} -> {}。占用中拒绝。
- admin.users {query?} -> [User]，手机号模糊搜索。
- admin.user.status {userId,status:'active'|'frozen'} -> User。
- admin.orders {userId?} -> [Order]。
- admin.logs {} -> [{id,action,target,detail,createdAt}]。
- forecasts.list {stationId?} -> {generatedAt,modelVersion,source,stations:[{stationId,stationName,hours:[{hour:1..24,time,loadKw,availableChargers,isPeak}],chargers:[{chargerId,code,hours:[{hour,time,loadKw,isPeak}]}]}],evaluation?:{...}}。用户可读站级；后台显示站/桩1/6/24h关键值。
- forecasts.run {} -> {running:true}。管理员启动异步预测任务。
- forecasts.status {} -> {running,lastError,lastRunAt}。

## 大屏合同

GET /api/dashboard 返回：
{generatedAt,dataCutoff,source:'课程演示业务数据',kpis:{totalChargingCount,totalRevenue,onlineChargers,registeredUsers,totalEnergyKwh},chargerStatus:[{key,label,value}],stationRanking:[{stationId,stationCode,stationName,energyKwh,revenue}],revenueTrend:[{date,revenue,orderCount}],hourlyHeatmap:[{weekday:0..6,hour:0..23,energyKwh}],chargerTypeRatio:[{type,label,count,energyKwh}],forecast24h:[{time,predictedLoadKw,actualLoadKw:null,availableChargers,isPeak}],stations:[Station],recentEvents:[{action,detail,createdAt}],forecastMeta:{generatedAt,modelVersion,source},forecastEval?:{...}}
大屏 revenue/totalRevenue 兼容现有组件使用元，不是分；业务 API 统一分。

## 预测任务合同

C++服务调用 Python 子进程、读取输出、通过 Qt 数据库连接保存结果。
预测入口 `ml/service.py`：
`uv run --project ml python -m ml.service --input INPUT.json --output OUTPUT.json`
INPUT: {generatedAt,stations:[{id,name,chargers:[Charger]}],sessions:[{stationId,chargerId,startedAt,endedAt,energyKwh}],timeScale:60}
OUTPUT: 与 forecasts.list DTO 一致。以当前时间为预测起点，24个逐小时预测；1/6/24要有值；站级与桩级求和一致；标注模型/数据来源，未有可靠数据时清楚显示基线估计，不能伪称训练模型。
真实数据回测另提供独立命令和报告，严格时间切分、无目标泄漏、按小时分摊守恒。原始公开数据不入Git。Python不直接写业务数据库。
