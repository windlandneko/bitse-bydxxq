# 充电平台数据库架构

## 1. 范围

数据库服务于用户端、管理端和预测/看板功能，当前采用 SQLite 3。核心流程包括：手机号登录、钱包充值、站点与电桩管理、预约、充电会话、订单结算、设备审计和负荷预测。

本期不引入数据库版本表、消息 outbox、物理日报汇总表、复杂 RBAC、真实支付和分时电价。需要这些能力时再单独扩展。

## 2. 基本约定

- 数据库文件由服务层统一持有，客户端不直接执行 SQL。
- 连接开启 `foreign_keys`、WAL 和 `busy_timeout`；写事务使用参数化查询。
- 时间以 UTC ISO-8601 文本保存，例如 `2026-09-04T01:00:00Z`。
- 金额由服务层按 Decimal/分计算，数据库保存两位小数；电量和功率保存三位小数。
- 主键使用 SQLite 的 `INTEGER PRIMARY KEY`。订单号、预约号、会话号和设备编号另设唯一业务标识。
- 交易、审计和状态历史只追加；订单中的价格是结算时快照，不随当前费率修改而变化。

## 3. 数据分层

| 层 | 表 | 作用 |
|---|---|---|
| 身份与资源 | `users`、`admins`、`stations`、`chargers`、`tariffs` | 账户、管理员、站点、设备和当前价格 |
| 交易 | `reservations`、`charging_sessions`、`orders`、`wallet_transactions` | 预约、充电、结算和钱包账本 |
| 运维 | `charger_status_history`、`admin_audit_logs` | 设备状态变化和管理员操作记录 |
| 分析 | `load_forecasts`、`v_station_availability`、`v_daily_revenue` | 预测结果和看板查询 |

主要关系：用户创建预约和充电会话，充电会话最多对应一个订单；站点包含电桩并配置费率；订单产生钱包流水；管理员操作产生审计记录。

## 4. 关键设计

### 4.1 用户与钱包

`users.phone` 是唯一登录标识，按文本保存，不在数据库限制手机号格式。新用户昵称由服务层生成 `用户` 加手机号后四位。`wallet_balance` 是当前余额快照，`wallet_transactions` 是账本事实。

充值金额为正，充电扣款为负。扣款前余额大于 0 时允许本次扣款，扣款后可以变为负值并直接显示欠费；扣款前余额小于等于 0 时，服务层阻止后续扣款。余额更新和流水插入必须在同一事务中完成。

### 4.2 站点、设备与费率

`stations` 保存站点基本信息和坐标，`chargers` 保存设备类型、功率、状态及累计运行数据。`(station_id, charger_code)` 唯一。

`tariffs` 只保存当前配置，每个站点和桩类型最多一条记录，使用 `(station_id, charger_type)` 唯一约束。当前不做生效区间和重叠检查；修改费率后，新订单读取新值，历史订单使用自身的价格快照。

### 4.3 预约、会话与订单

- 有效预约状态为 `active`、`started`；同一用户和同一电桩不能同时存在有效预约。
- `reservation_id` 在 `charging_sessions` 中唯一，`session_id` 在 `orders` 中唯一。
- 会话和订单保留 `user_id`、`station_id`、`charger_id` 便于查询和保存结算快照。它们之间的一致性由服务层在事务内校验，不使用跨表触发器。
- 预约和会话的时间、计量值、SoC、订单金额等保留必要的表内 `CHECK` 约束。

### 4.4 运维与预测

`charger_status_history` 用于故障追踪和设备统计；`admin_audit_logs` 记录冻结用户、修改站点/电桩、远程操作和价格调整。两者只追加，不承载业务状态机。

`load_forecasts` 保存站点预测区间、预测负荷、可用桩数、`is_peak`、模型版本和可选实际值。唯一键为 `(station_id, horizon_start, horizon_end, model_version)`。

看板统计直接查询订单和电桩，营收可使用 `v_daily_revenue`，设备数量使用 `v_station_availability`。本期不维护重复的 `station_daily_stats` 汇总表。

## 5. 约束与索引

数据库只保留能保护事实的约束：

- 手机号、管理员用户名、业务编号和幂等键唯一；外键默认 `ON DELETE RESTRICT`。
- 同一订单最多一笔 `charge` 钱包流水，避免重复结算。
- 部分唯一索引限制同一用户/电桩的有效预约和进行中的会话。
- 状态值、金额符号、余额流水加减关系、时间先后、坐标范围、功率/电量非负等由表内约束保证。
- 服务层负责跨表业务条件，例如冻结用户不能预约、预约状态才能开始会话、结束会话后才能结算。

已建立的普通索引集中在站点设备状态、用户/电桩预约、用户订单、钱包流水、审计时间和预测区间，用于当前列表和看板查询。暂不为尚未出现的查询添加索引。

## 6. 关键事务

### 预约

使用 `BEGIN IMMEDIATE`，检查用户状态、在途订单和目标电桩状态；插入预约、更新电桩状态并写状态历史后提交。幂等键重复时返回原预约。

### 开始充电

检查预约属于当前用户且为 `active`，再将预约置为 `started`、电桩置为 `charging`，插入会话并提交。重复请求返回已创建会话。

### 结束充电与结算

在一个写事务中读取会话和用户、计算费用、创建订单、执行余额规则、写入扣款流水、更新订单/会话/电桩和累计数据。任何一步失败都回滚；重复结算由会话唯一键和幂等键拦截。

### 管理与预测

管理员修改用户、站点或设备时，在同一事务中更新目标并写审计记录。预测结果按唯一键插入或更新，不覆盖其他模型版本。

## 7. 初始化与后续扩展

`schema.sql` 可重复执行，`seed.sql` 只用于开发/演示数据。种子数据覆盖管理员、5 个站点、混合 AC/DC 电桩、故障桩、31 天订单、负余额案例和预测记录。

真实支付、分时费率、消息推送、数据库迁移和高性能汇总表都留到需求明确且出现性能/可靠性证据后再增加。
